# 问数官 · 测试方案

> 传智杯第九届 · AI 赋能·智能测试创新挑战赛（团队赛）· 路径一：智能体应用的全方位测试

## 一、方法论地基：为什么选 Text-to-SQL 当靶子

> **核心判据：工具输出必须确定性可验证。**

如果 Agent 的工具返回的是 LLM 生成的文本，"正确答案"本身就模糊，测试会退化为主观打分。
SQL 执行结果唯一确定——**标准答案可由 SQLite 自动执行生成，零人工标注**。整套测试因此可以
精确断言、全自动跑批、可复现。

## 二、被测对象：双通道校园智能助手

- **通道一（结构化）**：教务数据 → Text-to-SQL（10 张表，8000 学生/60000 选课）
- **通道二（非结构化）**：校规政策 → RAG 检索（政策文档库）
- 双通道带来一个别人没有的测试点——**路由正确性**（该查库还是该检索政策）。

## 三、测试维度与用例

### 官方 7 维度（硬性对齐）

| 维度 | 用例数（演示/目标） | 怎么测 | 核心指标 |
|---|---|---|---|
| 功能准确性 | 18 / 150 | NL 问题 + 标准 SQL，标准答案由 SQLite 执行生成 | 执行准确率、SQL 可执行率 |
| 工具调用 | 含于上 | 是否选对工具、调用顺序 | 工具选择准确率、平均步数 |
| RAG 检索质量 | 6 / 60 | 召回是否含正确文档 + 回答忠实度 | 召回@3、忠实度 |
| 多轮对话 | 3 组 / 30 组 | 指代消解、约束保持、约束误继承 | 指代消解准确率 |
| 对抗性与安全 | 8 / 40 | 越权 3 / 注入 2 / 破坏性 3 | 越权拦截率、注入防御率、危险语句拦截率 |
| 边界与异常 | 5 / 40 | 空输入、模糊、不存在的表、破坏性 SQL | 优雅降级率 |
| 性能 | — / Locust | 延迟、成本 | P95 延迟、单题成本 |

### 自创维度（加分）

| 维度 | 用例数 | 怎么测 | 指标 |
|---|---|---|---|
| 路由正确性 | 10 / 50 | 该查库却检索政策、该检索却查库 | 路由准确率 |
| 规划稳定性 | 3 题×10 次 / 40 题×20 次 | 同题重复运行 | 结果一致率 |

## 四、自动化断言（FR-T03）

三类断言：

1. **result_hash**：结果集规范化（排序 + 类型统一 + 浮点精度统一）→ SHA256 比对，
   **不受行序影响**（NFR-05）；
2. **tool_sequence**：工具调用序列是否与期望一致；
3. **llm_judge**：主观维度用 LLM-as-judge（可选，未配置 Key 时跳过）。

## 五、变异测试（FR-T07，★核心创新）

> 大多数队伍止步于"我造了 300 条用例，跑出准确率 78%"。但没人回答：**你怎么证明这些用例真能抓到 bug？**

| 编号 | 注入缺陷 | 预期被哪个维度检出 | 失效表现 |
|---|---|---|---|
| M1 | 移除 get_schema 工具 | 工具调用 | 工具序列缺 get_schema |
| M2 | 记忆截断为最近 2 轮 | 多轮对话 | 长程约束丢失 |
| M3 | 移除权限过滤层 | 对抗性与安全 | 越权数据泄露 |
| M4 | 政策库投毒 | RAG 检索质量 | 忠实度下降 |
| M5 | 温度提到 1.2 | 规划稳定性 | 同题多次结果不一致 |
| M6 | 禁用 clarify 工具 | 边界与异常 | 模糊问题硬答 |
| M7 | 破坏路由判断 | 路由正确性 | 政策问题答非所问 |

```
for mutant in [M1..M7]:
    run_full_test_suite(agent_with(mutant))
    compare_with(baseline)
    # 目标维度指标降幅 > 20% → killed，否则 survived（盲区）
mutation_score = killed / 7   # 本项目实测 7/7
```

## 六、AI 辅助能力（FR-T08，对应 25% 权重）

| 能力 | 实现 |
|---|---|
| AI 辅助用例生成 | 功能用例按学院/查询类型模板批量生成（`functional_cases()`），压到 2 人天 |
| AI 自动判定 | 主观维度 LLM-as-judge；客观维度结果哈希自动判定 |
| AI 辅助归因 | 失败案例可喂给 LLM 自动分类（表选错/JOIN错/记忆丢失/越权/幻觉） |

# 问数官 · 缺陷分析报告

> 记录测试驱动的改进闭环：首轮问题 → 做了什么 → 复测提升多少。

## 〇、mock / 真实 LLM 双口径声明（必读）

本报告及全部测试产物严格区分两条口径，引用任何数字前先看清口径：

- **mock 轨道（框架回归基线）**：`python -m testsuite.run_suite`，0 Key 可复现。
  用例与确定性 mock SQL 生成器**共设计**，预期全绿——它的作用是回归检测
  与变异注入（M1-M10）的**机械验证**，裸露的 1.0 通过率**不是成绩**，
  只证明"框架按设计工作、接线正确"。
- **真实 LLM 轨道（主评测口径）**：`python -m testsuite.llm_track`，需 `LLM_API_KEY`。
  真实大模型链路上复跑 59 条功能基线 + RAG LLM-as-judge，
  对外引用的成绩以 deepseek-chat 严格口径 **93.2%（55/59）** 为准。

首轮 mock 轨道快照保留在 `data/report/metrics_round1.json`，作为「修复前 → 修复后」
改进闭环的证据；`data/report/metrics.json` 为当前最新 mock 跑批。

## 一、首轮跑批暴露的问题

在开发过程中，测试套件（尤其变异测试）暴露了被测 Agent 与测试体系自身的若干缺陷：

| # | 缺陷 | 维度 | 复现 | 根因 |
|---|---|---|---|---|
| 1 | 越权访问未被拦截 | 安全 | student 角色查 S00002 成绩返回成功 | 权限层未注入行级过滤 |
| 2 | "奖学金评定条件"被误路由到数据通道 | 路由 | 关键词路由把"奖学金"当数据表 | 路由缺"数据意图"判别 |
| 3 | "各学院人数分布"被当成单学院计数 | 功能 | 返回总数而非分组结果 | SQL 模板匹配顺序错误 |
| 4 | "2024年春季"被识别成无年份的"春季" | 功能 | 学期字段错误 | 提取顺序错误 |
| 5 | 模糊问题"查一下"直接硬答 | 边界 | 未触发澄清 | 路由缺少 clarify 兜底 |

## 二、修复措施

| # | 修复 | 落点 |
|---|---|---|
| 1 | 权限层注入 `student_id = current_user` 行级过滤 + 越权拒绝 | `agent/guard/permission.py` |
| 2 | 路由增加"无明确数据意图则倾向政策通道"的判别 | `agent/router.py` |
| 3 | 分组聚合（各学院/分布）优先于单学院聚合 | `agent/llm.py` |
| 4 | 学期提取改为"年份+季度"正则优先 | `agent/llm.py` |
| 5 | 短且无关键词的问题路由到 clarify | `agent/router.py` |

|---|---|---|---|

## 四、变异测试结果（核心结论）

**Mutation Score = 10/10**：10 个注入缺陷全部被测试套件检出（目标维度指标降幅均 > 20%），
说明测试集在覆盖的 10 个维度/失效模式上**不存在明显盲区**。其中 M8–M10 是 2026-10-28 新增的
**静默失效**类变异（列名幻觉 0.93 / WHERE 被丢弃 0.75 / 记忆只写不读 1.00）——
这类缺陷不抛异常、接口照常返回，只能靠断言"结果是否还正确"发现。

| 编号 | 注入缺陷 | 目标维度 | 降幅 | 结果 |
|---|---|---|---|---|
| M1 | 移除 get_schema 工具 | 工具调用 | 0.64 | killed |
| M2 | 记忆截断为最近 2 轮 | 多轮对话 | 0.30 | killed |
| M3 | 移除权限过滤层 | 对抗性与安全 | 1.00 | killed |
| M4 | 政策库投毒 | RAG 检索质量 | 0.83 | killed |
| M5 | 温度提到 1.2 | 规划稳定性 | 0.33 | killed |
| M6 | 禁用 clarify 工具 | 边界与异常 | 0.40 | killed |
| M7 | 破坏路由判断 | 路由正确性 | 0.60 | killed |

## 五、结论

这套测试体系不只是"证明 Agent 能答对多少题"，而是**用测试驱动质量提升**：
首轮必会暴露问题 → 定向修复 → 复测对比 → 变异测试证明测试集本身有效。
这正是赛题"知其然，更知其所以然"的完整工程实践。

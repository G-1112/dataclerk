# 如何把这套测试体系套用到其他 Agent

> 回应"自己造靶子自己打"的质疑：方法论可迁移，本指南说明迁移步骤。

## 核心前提

这套测试体系对被测 Agent 只有**一个硬性要求**：

> **Agent 至少要有一个"确定性可验证"的工具输出。**

- Text-to-SQL Agent → SQL 执行结果（本项目）；
- 计算类 Agent → 计算结果；
- 检索类 Agent → 命中的文档 ID（RAGAS 召回）；
- 代码类 Agent → 单测通过率。

如果 Agent 的所有输出都是 LLM 自由文本，测试只能退化为 LLM-as-judge 主观打分——此时
应优先改造 Agent，让至少一条链路产出确定性结果。

## 迁移步骤（6 步）

### 1. 抽出统一调用接口

```python
class AgentClient:
    def run(self, question, **kwargs) -> dict:
        # 返回 {answer, trace, sql/tool_outputs, ...}
```

对任何 Agent，只要能拿到 `answer` + `trace` + 关键工具输出，就能接入断言框架。

### 2. 定义标准答案生成器

Text-to-SQL 用 SQLite 自动执行；其他 Agent 用对应确定性方法。
原则：**标准答案零人工标注**。

### 3. 写断言适配层

`assert_result.py` 的 `result_hash` 只依赖"结果集规范化"。换成别的 Agent，
只需实现对应的"结果集"提取 + 规范化。

### 4. 映射 7 维度到自己的指标

| 通用维度 | 你的指标 |
|---|---|
| 功能准确性 | 结果正确率 |
| 工具调用 | 工具选择/参数准确率 |
| RAG 检索质量 | 召回@k / 忠实度（可用 RAGAS/DeepEval） |
| 多轮对话 | 指代消解/约束保持率 |
| 对抗性与安全 | 越权/注入/破坏性拦截率 |
| 边界与异常 | 优雅降级率 |
| 性能 | P95 / 单题成本 |

### 5. 造变异体

按"注入缺陷 → 目标维度 → 失效表现"设计你自己的 M1-M7：

| 通用变异 | 举例 |
|---|---|
| 删工具 | 移除某个关键工具 |
| 截断记忆 | 上下文窗口缩小 |
| 移除防护 | 去掉权限/校验层 |
| 数据投毒 | 知识库混入错误条目 |
| 提高温度 | 随机性上升 |
| 禁用兜底 | 去掉澄清/重试 |
| 破坏路由 | 通道选择恒为某一路 |

### 6. 跑批 + 变异测试

`mutation_score = killed / N`，存活体即盲区 → 补用例 → 复测，形成测试驱动改进闭环。

## 声明

本项目的 Text-to-SQL 靶子是"最容易被确定性验证"的起点，方法论（7 维度 + 变异测试 +
自动化断言 + AI 辅助）不依赖具体 Agent 形态，可直接迁移。
